## 9. Implementação demonstrativa

A implementação apresentada nesta entrega foi propositalmente mantida simples e concentrada no ponto em que o padrão Prototype é aplicado.

Embora o fluxo funcional de emissão do CRLV-e envolva verificações relacionadas a débitos, restrições e situação do licenciamento, o objetivo do código não é reproduzir integralmente o funcionamento do sistema analisado. O foco da implementação é demonstrar, de maneira isolada e verificável, como um documento-base pode ser utilizado como protótipo para a criação de novas instâncias de CRLV-e.

Dessa forma, os participantes do padrão são representados da seguinte maneira:

| Participante GoF | Implementação |
|--|--|
| Prototype | `DocumentoVeicular` |
| ConcretePrototype | `CRLVe` |
| Client | `EmissorCRLVe` |
| Objeto auxiliar | `DadosVeiculo` |

### 9.1 Código

O código completo está no arquivo [`prototype_crlve.py`](https://github.com/UnBArqDsw2026-2-Turma02/2026.2-T02-_G6_ProjetoAplicativoMovel_Entrega03/blob/feature/subequipe-1/docs/Base/Relatorios/SubEquipe_01/Yuri/codigo/prototype_crlve.py) e pode ser executado com `python prototype_crlve.py`.

```python
from abc import ABC, abstractmethod
from copy import deepcopy
from dataclasses import dataclass


@dataclass
class DadosVeiculo:
    placa: str
    renavam: str
    exercicio: int


# Prototype
class DocumentoVeicular(ABC):

    @abstractmethod
    def clonar(self):
        """Cria uma cópia do documento."""
        ...


# ConcretePrototype
class CRLVe(DocumentoVeicular):

    def __init__(self) -> None:
        # Dados comuns ao modelo do documento
        self.tipo = "CRLV-e"
        self.orgao_emissor = "Órgão de trânsito"
        self.versao_layout = "2026.1"

        # Dados específicos de cada emissão
        self.placa = None
        self.renavam = None
        self.exercicio = None

    def clonar(self):
        return deepcopy(self)

    def preencher(self, dados: DadosVeiculo) -> None:
        self.placa = dados.placa
        self.renavam = dados.renavam
        self.exercicio = dados.exercicio

    def __str__(self) -> str:
        return (
            f"{self.tipo} | "
            f"Placa: {self.placa} | "
            f"RENAVAM: {self.renavam} | "
            f"Exercício: {self.exercicio}"
        )


# Client
class EmissorCRLVe:

    def __init__(self, prototipo: DocumentoVeicular) -> None:
        self.prototipo = prototipo

    def emitir(self, dados: DadosVeiculo) -> DocumentoVeicular:
        documento = self.prototipo.clonar()
        documento.preencher(dados)
        return documento


# Execução demonstrativa
if __name__ == "__main__":

    print("\n== PROTOTYPE ==")

    prototipo = CRLVe()
    emissor = EmissorCRLVe(prototipo)

    documento_1 = emissor.emitir(
        DadosVeiculo(
            placa="ABC1D23",
            renavam="12345678900",
            exercicio=2026
        )
    )

    documento_2 = emissor.emitir(
        DadosVeiculo(
            placa="XYZ9A87",
            renavam="98765432100",
            exercicio=2026
        )
    )

    print(documento_1)
    print(documento_2)

    print("\nObjetos independentes:")
    print(documento_1 is not documento_2)

    print("\nPrototype permaneceu sem dados específicos:")
    print(f"Placa: {prototipo.placa}")
    print(f"RENAVAM: {prototipo.renavam}")
    print(f"Exercício: {prototipo.exercicio}")
```

### 9.2 Explicação da implementação

#### DadosVeiculo

A classe `DadosVeiculo` representa apenas os dados variáveis necessários para individualizar cada documento emitido.

```python
@dataclass
class DadosVeiculo:
    placa: str
    renavam: str
    exercicio: int
```

Ela não representa um participante do padrão GoF; funciona apenas como estrutura auxiliar para transportar os dados específicos de cada emissão.

#### DocumentoVeicular — Prototype

A classe abstrata `DocumentoVeicular` representa o participante **Prototype**.

```python
class DocumentoVeicular(ABC):

    @abstractmethod
    def clonar(self):
        ...
```

Sua responsabilidade é estabelecer que documentos utilizados como protótipos devem disponibilizar uma operação de clonagem. O cliente, portanto, não precisa conhecer todos os detalhes envolvidos na construção de uma nova instância.

#### CRLVe — ConcretePrototype

A classe `CRLVe` representa o participante **ConcretePrototype**. Ela mantém informações comuns ao modelo do documento e também os campos que serão individualizados em cada emissão.

O ponto principal da implementação está no método:

```python
def clonar(self):
    return deepcopy(self)
```

A função `deepcopy` cria uma nova instância independente a partir do objeto-base. Depois da clonagem, somente os dados específicos daquela emissão são preenchidos:

```python
def preencher(self, dados: DadosVeiculo) -> None:
    self.placa = dados.placa
    self.renavam = dados.renavam
    self.exercicio = dados.exercicio
```

#### EmissorCRLVe — Client

A classe `EmissorCRLVe` representa o participante **Client**.

```python
class EmissorCRLVe:

    def __init__(self, prototipo: DocumentoVeicular) -> None:
        self.prototipo = prototipo
```

Ao realizar uma emissão, o Client não instancia diretamente um novo `CRLVe`. Em vez disso, solicita uma cópia ao Prototype:

```python
def emitir(self, dados: DadosVeiculo) -> DocumentoVeicular:
    documento = self.prototipo.clonar()
    documento.preencher(dados)
    return documento
```

Esse é o trecho que evidencia diretamente o uso do padrão Prototype.

#### Bloco de execução — montagem do padrão

O bloco `if __name__ == "__main__"` faz o papel de quem configura a aplicação: cria **uma única vez** o objeto-base (`CRLVe()`), entrega-o ao `EmissorCRLVe` e, a partir daí, solicita as emissões apenas por meio de `emitir(dados)`. Ele também exibe as verificações que comprovam o padrão: os documentos emitidos são objetos diferentes e o protótipo continua sem placa, Renavam e exercício.

### 9.3 Relação entre o fluxo documentado e o código

O fluxo funcional completo documentado nesta entrega permanece relevante para contextualizar a aplicação do padrão:

```text
Selecionar veículo
        ↓
Verificar condições para emissão
        ↓
Emissão autorizada
        ↓
Obter documento-base
        ↓
clonar()
        ↓
Preencher dados do veículo
        ↓
CRLV-e individualizado
```

Entretanto, a implementação demonstrativa começa deliberadamente na etapa de criação do documento. As verificações de débitos, restrições e regularidade do licenciamento pertencem ao contexto funcional levantado nas etapas anteriores, mas não precisam ser novamente implementadas para demonstrar o GoF Prototype.

Essa separação evita transformar a demonstração do padrão em uma reprodução especulativa de toda a arquitetura interna do sistema observado.

## 10. Padrão em execução

### 10.1 Execução do padrão

Na demonstração é criado apenas um objeto-base:

```python
prototipo = CRLVe()
```

Esse objeto é fornecido ao Client:

```python
emissor = EmissorCRLVe(prototipo)
```

Duas emissões são realizadas a partir do mesmo Prototype. A saída da execução é:

```text
== PROTOTYPE ==
CRLV-e | Placa: ABC1D23 | RENAVAM: 12345678900 | Exercício: 2026
CRLV-e | Placa: XYZ9A87 | RENAVAM: 98765432100 | Exercício: 2026

Objetos independentes:
True

Prototype permaneceu sem dados específicos:
Placa: None
RENAVAM: None
Exercício: None
```

O resultado `True` demonstra que os documentos produzidos são objetos independentes. Além disso, o Prototype original permanece sem os dados particulares dos documentos emitidos, mostrando que a personalização de uma cópia não altera o objeto-base.
