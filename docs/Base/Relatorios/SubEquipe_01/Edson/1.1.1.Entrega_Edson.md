### GoF Criacional
#### Contexto (Problema)

No aplicativo do Detran-DF, o usuário informa a placa e o Renavam do veículo para consultar débitos, restrições, financiamentos ou emitir o "nada consta". Ao analisar o fluxo do aplicativo, percebe-se que todas as quatro opções partem da mesma tela inicial e entregam um retorno direto ao usuário. No entanto, embora a interface precise lidar com essas consultas de forma uniforme, cada uma delas é implementada de maneira diferente no sistema. Sem um padrão o cliente escolheria qual consulta instanciar utilizando uma estrutura condicional:

```python
if tipo == "debitos":
    consulta = ConsultaDebitos()
elif tipo == "restricoes":
    consulta = ConsultaRestricoes()
elif tipo == "financiamentos":
    consulta = ConsultaFinanciamentos()
```

Contudo essa abordagem é incorreta, visto que causa:
   * Acoplamento: o cliente conhece todas as classes concretas.
   * Violação do Open/Closed: cada novo tipo (por exemplo, “consulta de multas”) obriga a editar o cliente.
   * Duplicação: o mesmo if/elif tende a se repetir em cada tela ou fluxo que faz consultas.

Aqui entra o Factory Method:
  O padrão move a decisão de qual consulta criar para subclasses de um Creator. O cliente passa a depender apenas da abstração Consulta, e incluir um novo tipo significa adicionar duas classes (o produto e o seu creator), sem alterar o código existente.

### Implementação do diagrama em código

```python

from abc import ABC, abstractmethod
from dataclasses import dataclass, field
from datetime import date

class BaseDetran:
    """Simulação das fontes de dados que o app consulta (inferido, não observado)."""

    def __init__(self) -> None:
        self.debitos = {"98765432100": ["IPVA 2026: R$ 1.250,00", "Multa: R$ 195,23"]}
        self.restricoes = {"98765432100": ["Restrição judicial (RENAJUD)"]}
        self.financiamentos = {"55555555555": ["Alienação fiduciária - Banco X"]}

@dataclass
class ResultadoConsulta:
    tipo: str
    itens: list[str] = field(default_factory=list)

    @property
    def limpo(self) -> bool:
        return not self.itens

    def __str__(self) -> str:
        if self.limpo:
            return f"[{self.tipo}] nada consta"
        return f"[{self.tipo}] " + "; ".join(self.itens)


# Product
class Consulta(ABC):
    def __init__(self, base: BaseDetran) -> None:
        self._base = base

    @abstractmethod
    def executar(self, renavam: str) -> ResultadoConsulta: ...


# Concrete Products
class ConsultaDebitos(Consulta):
    def executar(self, renavam: str) -> ResultadoConsulta:
        return ResultadoConsulta("Débitos", self._base.debitos.get(renavam, []))


class ConsultaRestricoes(Consulta):
    def executar(self, renavam: str) -> ResultadoConsulta:
        return ResultadoConsulta("Restrições", self._base.restricoes.get(renavam, []))


class ConsultaFinanciamentos(Consulta):
    def executar(self, renavam: str) -> ResultadoConsulta:
        return ResultadoConsulta("Financiamentos", self._base.financiamentos.get(renavam, []))


class ConsultaNadaConsta(Consulta):
    def executar(self, renavam: str) -> ResultadoConsulta:
        itens = (
            self._base.debitos.get(renavam, [])
            + self._base.restricoes.get(renavam, [])
            + self._base.financiamentos.get(renavam, [])
        )
        return ResultadoConsulta("Nada Consta", itens)

# Creator
class ConsultaCreator(ABC):
    def __init__(self, base: BaseDetran) -> None:
        self._base = base

    @abstractmethod
    def criar_consulta(self) -> Consulta:
        """Factory Method: subclasses decidem qual Consulta instanciar."""

    def consultar(self, crv: CRV) -> ResultadoConsulta:
        consulta = self.criar_consulta()
        return consulta.executar(crv.veiculo.renavam)


# Concrete Creators
class DebitosCreator(ConsultaCreator):
    def criar_consulta(self) -> Consulta:
        return ConsultaDebitos(self._base)


class RestricoesCreator(ConsultaCreator):
    def criar_consulta(self) -> Consulta:
        return ConsultaRestricoes(self._base)


class FinanciamentosCreator(ConsultaCreator):
    def criar_consulta(self) -> Consulta:
        return ConsultaFinanciamentos(self._base)


class NadaConstaCreator(ConsultaCreator):
    def criar_consulta(self) -> Consulta:
        return ConsultaNadaConsta(self._base)


# Testando

if __name__ == "__main__":
    base = BaseDetran()

    print("\n== FACTORY METHOD ==")
    for creator in (DebitosCreator(base), RestricoesCreator(base),
                    FinanciamentosCreator(base), NadaConstaCreator(base)):
        print(creator.consultar(crv_pendente))

```

Escrevi uma primeira versão do código reunindo, em um único arquivo, Singleton, Factory Method e Builder. Para verificar se ela estava coerente como GoF criacional, enviei o código ao Claude.

*prompt:*

            ```python
                
            from abc import ABC, abstractmethod

            
            # singleton: sistema central do DETRAN-DF
            class SistemaDetranDF:
                """Garante uma única instância para consultar débitos e validar dados."""
                _instance = None
                
                def __new__(cls):
                    if cls._instance is None:
                        cls._instance = super().__new__(cls)
                        # Simulação de base de dados: renavam -> possui debitos?
                        cls._instance._base_debitos = {
                            "12345678901": False,  # sem debitos
                            "98765432100": True,   # com debitos
                        }
                    return cls._instance

                def verificar_debitos(self, renavam: str) -> bool:
                    return self._base_debitos.get(renavam, False)


    
            # factory method: tipos de veiculos (Product & ConcreteProducts)
            class Veiculo(ABC):
                def __init__(self, placa, cor, modelo, ano, renavam, crv, cpf_dono, estado):
                    self.placa = placa
                    self.cor = cor
                    self.modelo = modelo
                    self.ano = ano
                    self.renavam = renavam
                    self.crv = crv
                    self.cpf_dono = cpf_dono
                    self.estado = estado

                @abstractmethod
                def consultar_veiculo(self) -> str:
                    pass


            class Carro(Veiculo):
                def consultar_veiculo(self) -> str:
                    return (f"[CARRO] Modelo: {self.modelo} ({self.ano}) | Placa: {self.placa}\n"
                            f"Renavam: {self.renavam} | CPF Dono: {self.cpf_dono} | UF: {self.estado}")


            class Moto(Veiculo):
                def consultar_veiculo(self) -> str:
                    return (f"[MOTO] Modelo: {self.modelo} ({self.ano}) | Placa: {self.placa}\n"
                            f"Renavam: {self.renavam} | CPF Dono: {self.cpf_dono} | UF: {self.estado}")


            # builder: construção Passo a Passo do Veículo
            class VeiculoBuilder:
                """Permite construir o objeto Veiculo de forma fluida e sem construtor gigante."""
                def __init__(self, tipo_veiculo: str = "carro"):
                    self.tipo_veiculo = tipo_veiculo
                    self.placa = ""
                    self.cor = ""
                    self.modelo = ""
                    self.ano = 0
                    self.renavam = ""
                    self.crv = ""
                    self.cpf_dono = ""
                    self.estado = "DF" 

                def com_placa(self, placa: str):
                    self.placa = placa
                    return self

                def com_dados(self, modelo: str, cor: str, ano: int):
                    self.modelo = modelo
                    self.cor = cor
                    self.ano = ano
                    return self

                def com_documentacao(self, renavam: str, crv: str, cpf_dono: str, estado: str = "DF"):
                    self.renavam = renavam
                    self.crv = crv
                    self.cpf_dono = cpf_dono
                    self.estado = estado
                    return self

                def build(self) -> Veiculo:
                    """Factory Method interno para decidir o tipo concreto."""
                    if self.tipo_veiculo.lower() == "moto":
                        return Moto(self.placa, self.cor, self.modelo, self.ano, self.renavam, self.crv, self.cpf_dono, self.estado)
                    return Carro(self.placa, self.cor, self.modelo, self.ano, self.renavam, self.crv, self.cpf_dono, self.estado)


            # Transferência e CRLV

                def __init__(self, cpf_novo_dono: str):
                    self.cpf_comprador = cpf_novo_dono
                    self.detran = SistemaDetranDF()  # Usa o Singleton

                def transferir(self, veiculo: Veiculo) -> str:
            ```

            Esse código está coerente como um GoF criacional?

*resultado:* a IA apontou que o Singleton estava bem aplicado, mas que o trecho que eu havia chamado de Factory Method **não era** o padrão. A escolha entre `Carro` e `Moto` acontecia por um `if` dentro do método `build()` do Builder, o que caracteriza uma *Simple Factory* (que não é um padrão GoF). Não havia um **Creator** nem subclasses sobrescrevendo um método de criação, que são os elementos que definem o Factory Method.

**Validação e decisão:** Conferi a afirmação com o material da disciplina e confirmei que os participantes Creator e Concrete Creator realmente estavam ausentes. Concordei com a crítica e, em vez de manter o código misturado, decidi aplicar o Factory Method ao fluxo de **Consulta de Veículo**, em que existem quatro variações (débitos, restrições, financiamentos e nada consta) com a mesma interface.
